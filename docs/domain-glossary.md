# 도메인 용어집 (프론트엔드 관점)

전체 도메인 용어집의 원본은 `commercehub-be` 저장소의 [`docs/domain-glossary.md`](https://github.com/commercehub/commercehub-be/blob/main/docs/domain-glossary.md)이며, 이 문서는 프론트엔드 화면 구현 시 특히 자주 헷갈리는 부분만 발췌·보강한 것입니다. 두 문서 내용이 다르면 백엔드 저장소 쪽을 원본으로 간주합니다.

## 화면 문구 ↔ 서버 상태값

| 화면에 노출되는 문구(기획/카피) | 서버 상태 Enum | 비고 |
| --- | --- | --- |
| "결제 완료" | `PAID` | "주문 접수"라는 문구도 같은 상태를 가리킬 수 있음 — 화면별로 카피가 다를 수 있으니 Enum 기준으로 분기 |
| "상품 준비중" | `READY_FOR_SHIPMENT` | |
| "배송조회 가능" / "배송중" | `IN_TRANSIT` | 두 문구 모두 같은 상태, 노출 위치(목록 vs 상세)에 따라 카피만 다름 |
| "일부 상품 취소됨" | `PARTIALLY_CANCELLED` | |

문구는 `locales/ko.json`에서 관리하며 Enum 값을 키로 사용합니다. **컴포넌트 코드에 문구를 직접 하드코딩하지 않습니다.**

## 상품/옵션 관련

| 기획 용어 | 프론트 구현 시 유의점 |
| --- | --- |
| 옵션 | `optionGroup`/`optionValue` 두 단계 구조. 단일 셀렉트 UI로 단순화하기 전에 옵션 그룹이 1개인지 여러 개인지(예: 색상+사이즈 조합) 반드시 API 응답을 확인 |
| 옵션조합(SKU) | 장바구니 담기/재고 체크는 항상 SKU 단위로 이루어짐. "상품 하나가 품절"이라는 표현은 화면에서만 쓰고, 로직에서는 절대 상품 단위로 품절을 판단하지 않음 |
| 대표 이미지 / 상세 이미지 | 목록(`thumbnailImageUrl`)과 상세(`detailImageUrls`)는 다른 필드. 목록 캐러셀에 상세 이미지를 재사용하면 안 됨(용량/비율이 다름) |

## 장바구니

| 기획 용어 | 프론트 구현 시 유의점 |
| --- | --- |
| 장바구니 병합 | 비로그인 → 로그인 전환 시 로컬스토리지 장바구니와 서버 장바구니를 병합하는 API를 호출해야 함. 프론트에서 임의로 두 목록을 합쳐서 렌더링하면 안 됨(수량 초과/품절 판정은 서버가 최종 결정) |
| 최근 본 상품 | 장바구니 아이콘과 혼동하지 않도록 별도 아이콘/영역 사용 |

## 회원/혜택

| 기획 용어 | 프론트 구현 시 유의점 |
| --- | --- |
| 등급(멤버십) | `membershipTier`. "쿠폰 등급"이라는 별도 개념과 화면에서 인접 배치 시 라벨을 명확히 구분(사용자 혼동 이슈가 실제로 있었음) |
| 적립금 | 화면 표기는 항상 "원" 단위, 소수점 노출 금지 (`formatKrw()` 사용) |

## 신규 용어 추가 절차

프론트에서만 쓰는 화면 용어가 새로 생기면 이 문서에 먼저 추가하고, 서버 상태와 관련된 개념이면 `commercehub-be`의 원본 용어집에도 함께 반영되도록 백엔드 담당자에게 공유합니다.
