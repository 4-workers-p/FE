# 배포 체크리스트 및 정책 (commercehub-fe)

프론트엔드도 개발실 공통 Git 정책(브랜치 전략, 커밋 규칙)을 따릅니다. 이 문서는 프론트엔드 저장소에 특화된 배포 전 체크리스트를 다룹니다.

## 1. 브랜치/PR 정책 (공통 정책 발췌)

- `main`(운영) / `develop`(스테이징) / `feature/*`, `fix/*`
- PR 승인: 프론트 리드 또는 지정 리뷰어 1인 필수
- 디자인 변경(레이아웃, 신규 컴포넌트, 색상/타이포)이 포함된 PR은 **디자이너 코멘트 승인**이 추가로 필요합니다 (자세한 절차는 [`design-collaboration.md`](design-collaboration.md))
- PR에는 Vercel Preview 링크가 자동으로 달립니다. 리뷰어는 코드뿐 아니라 Preview 화면도 확인합니다.

## 2. 배포 전 체크리스트

- [ ] `pnpm build` 로컬 성공 확인
- [ ] Playwright E2E 스위트(핵심 구매 흐름) 통과
- [ ] Lighthouse 성능 점수 확인 (모바일 기준 Performance 85점 이상 유지, 하락 시 원인 파악 전 배포 보류)
- [ ] 환경변수 변경 시 Vercel/CloudFront 양쪽 설정 동기화 확인
- [ ] 주요 상품/장바구니/결제 페이지 스테이징에서 수동 스모크 테스트

## 3. 성능 기준

| 지표 | 기준 |
| --- | --- |
| Lighthouse Performance (Mobile) | 85점 이상 |
| First Load JS (핵심 페이지) | 200KB 이하 |
| Core Web Vitals - LCP | 2.5초 이하 |

기준 미달 시 배포를 진행하되, 다음 스프린트에 개선 티켓을 반드시 등록합니다(배포 차단 여부는 하락폭에 따라 프론트 리드가 판단).

## 4. 배포 시간대

백엔드와 동일하게 **평일 오후 2시~5시** 배포를 원칙으로 하고, 금요일 배포는 지양합니다. 단, 프론트엔드는 정적 리소스 배포 특성상 롤백이 빠르므로(CloudFront 무효화) 긴급도가 낮은 UI 수정은 이 시간대 외에도 배포할 수 있습니다(파트장 사전 공유 필요).

## 5. 롤백

- Vercel: 이전 배포로 즉시 롤백 (Vercel 대시보드, 1분 내 완료)
- 운영(CloudFront + S3): 이전 빌드 아티팩트를 S3에 재업로드 후 CloudFront 캐시 무효화 (약 5분 소요)
- 롤백 후 반드시 `#commercehub-incident`에 공유
